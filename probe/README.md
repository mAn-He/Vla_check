# probe — 같은 걸 보여주고 뭐가 다른지 보는 도구

## 뭐가 문제였냐면

로봇 모델 두 개를 비교하는데 성적표가 똑같이 나왔습니다.

```
GR00T      98%
OpenVLA   100%
```

50번 시켜서 49번, 50번 성공한 겁니다. 이 정도면 그냥 동점이에요.
둘 중 뭐가 나은지 말할 수가 없습니다.

그래서 다른 걸 보기로 했습니다.
**같은 장면을 두 모델한테 보여주고, 각자 뭘 하려 하는지 비교**하는 겁니다.
결과만 보지 말고 과정을 보자는 거죠.

---

## 왜 "녹화해서 다시 틀어주는" 방식인가

그냥 각자 시켜보면 될 것 같지만, 안 됩니다.

로봇이 움직이면 보이는 장면이 계속 바뀝니다.
A모델이 왼쪽으로 가면 왼쪽 풍경을 보게 되고, B모델이 오른쪽으로 가면 오른쪽을 보게 됩니다.
**둘이 서로 다른 걸 보고 있으니 반응이 달라도 당연합니다.** 비교가 안 되죠.

그래서 이렇게 합니다.

1. 일단 한 번만 실제로 시켜보고, 로봇이 본 장면들을 전부 **녹화**합니다
2. 그 녹화본을 두 모델한테 **똑같이** 틀어줍니다
3. 각자 뭘 하려 하는지 받아 적습니다

로봇은 실제로 안 움직입니다. 그냥 "이 장면에서 뭘 하고 싶어?"라고 묻기만 하는 거예요.
같은 시험지를 두 사람한테 주는 것과 같습니다.

---

## 어떻게 쓰나

```bash
source .venvs/libero/bin/activate
```

### 1단계 — 녹화하기

```bash
python probe/dump_episode.py --model groot_n17_libero --suite libero_spatial --task-id 0
```

로봇을 한 번 실제로 굴리면서 매 순간의 장면을 저장합니다.
어느 모델로 굴려도 상관없습니다. 어차피 녹화본만 쓸 거니까요.

`probe/episodes/` 폴더에 파일이 하나 생깁니다.

### 2단계 — 모델마다 틀어주기

```bash
# 첫 번째 모델
python probe/compare.py --episode probe/episodes/libero_spatial_t0_by-groot_n17_libero.npz \
                        --model groot_n17_libero
```

끝나면 **서버를 다른 모델로 바꿔 띄우고** 같은 명령을 한 번 더:

```bash
python probe/compare.py --episode probe/episodes/libero_spatial_t0_by-groot_n17_libero.npz \
                        --model openvla_oft_libero
```

파일 이름은 그대로 둡니다. 같은 녹화본을 써야 비교가 되니까요.

> 급하면 `--grid 0`을 붙이세요. 30초면 끝납니다.
> 대신 "어디를 봤는지" 분석은 빠집니다.

### 3단계 — 그림 뽑기

```bash
python probe/compare.py --render     # 분석용 그래프
python probe/storyboard.py           # 사람이 보는 카드
```

## 무슨 그림이 나오나

### 사람이 보기 편한 쪽 — `storyboard.py`

**`story_frame00.png` 같은 것들** — 한 장면에서 벌어진 일 전부를 한 장에 담았습니다.

```
맨 위     이번 장면에서 로봇이 받은 지시문 (원문 그대로)
윗줄      실제 장면 사진 | 손목 카메라 사진 | 모델별로 어디를 봤는지
아랫줄    모델별로 어디로 가려는지 (위에서 내려다본 경로)
          그 순간의 명령값 막대그래프
          "아래로 내려감, 손은 벌린 채" 같이 말로 풀어놓은 판단
```

두 모델의 경로는 **눈금을 똑같이 맞춰서** 그립니다. 안 그러면 겹쳐볼 수가 없어요.

**`story_language.png`** — 이게 제일 재밌습니다.

똑같은 사진을 보여주고 **말만 바꿔서** 물어봅니다.

| 뭘 바꿨나 | 예시 |
|---|---|
| 원본 | "검은 그릇을 집어서 접시에 놓아라" |
| 말만 바꿈 | "검은 그릇을 잡아서 접시에 올려라" |
| 집으라는 물건을 바꿈 | "**접시**를 집어서 접시에 놓아라" |
| 아무 말도 안 함 | (빈 문장) |
| 엉뚱한 말 | "오늘 날씨가 좋네요" |

5줄이 전부 똑같은 경로를 그리면 → **모델이 글을 안 읽고 있다**는 뜻입니다.
사진만 보고 움직이는 거죠.

특히 세 번째가 핵심입니다. 집으라는 물건을 바꿨는데도 똑같이 움직인다면,
그 모델은 "뭘 집으라는 건지"를 신경 쓰지 않는다는 얘기입니다.

**`story_overview.png`** — 처음부터 끝까지 훑어보는 용도.
어느 시점에서 두 모델이 갈라지는지 한눈에 보입니다.

### 분석용 — `compare.py --render`

| 파일 | 뭘 보나 |
|---|---|
| `01_action_disagreement` | 언제 두 모델이 제일 다르게 판단했나 |
| `02_action_timeseries` | 명령값 7개가 시간에 따라 어떻게 움직이나 |
| `03_intent_trajectory` | 같은 장면에서 어디로 가려 하나 |
| `04_language_probe` | 말을 바꿨을 때 얼마나 반응하나 (숫자) |
| `05_camera_reliance` | 정면 카메라와 손목 카메라 중 뭘 더 믿나 |
| `06_saliency_<모델>` | 사진의 어느 부분을 보고 판단하나 |

## "어디를 봤는지"는 어떻게 아나

모델 속을 들여다볼 수는 없습니다. 대신 이렇게 알아냅니다.

사진을 바둑판처럼 64칸으로 나눕니다.
한 칸씩 회색으로 가려보면서, **가렸을 때 행동이 얼마나 달라지는지** 잽니다.

- 그릇을 가렸더니 행동이 확 바뀌었다 → 그릇을 보고 판단하고 있었다
- 배경을 가렸는데도 그대로다 → 배경은 안 보고 있었다

이걸 색으로 칠해서 사진 위에 덮으면 "어디가 중요했는지" 지도가 됩니다.

> **용어 주의.** 이걸 "어텐션(attention)"이라고 부르면 안 됩니다.
> 어텐션은 모델 내부의 실제 가중치고, 이건 **가렸을 때 결과가 얼마나 흔들리나**를 잰 겁니다.
> 관련은 있지만 다른 겁니다.

## 결과 읽을 때 조심할 것

### 1. 이 모델들은 뇌가 하나입니다

"인지 / 계획 / 제어"로 나눠서 분석하지만, 실제로 모델 안에 그런 부품이 따로 있는 게 아닙니다.
사진과 글을 넣으면 명령값이 바로 튀어나오는 통짜 구조예요.

세 층은 **우리가 보기 편하려고 나눈 틀**입니다.
모델 내부를 뜯는 게 아니라, 입력을 바꿔보고 출력이 어떻게 달라지나 관찰하는 방식이라
어떤 모델에든 똑같이 쓸 수 있다는 게 장점입니다.

### 2. 한 번 본 걸로 단정하지 마세요

지금 결과는 **태스크 하나, 장면 하나, 시드 하나**입니다.
번호를 바꿔가며 여러 번 돌려보고 같은 패턴이 나와야 말할 수 있습니다.

### 3. 이 벤치마크는 애초에 말이 별로 안 중요합니다

LIBERO-Spatial의 과제 10개가 전부 이런 식입니다.

```
"검은 그릇을 접시에 놓아라"  ← 집는 물건이 항상 같음
```

위치 설명만 조금씩 다릅니다.
그러니까 모델이 "뭘 집을지"를 안 봐도 성적이 잘 나오는 게 이상하지 않아요.
`libero_object`(집는 물건이 실제로 바뀜)에서도 같은지 확인해야 합니다.

### 4. 말 바꾸기는 기계적으로 합니다

"검은 그릇 → 접시"처럼 단어만 바꿔치기하는 방식이라
문장이 좀 어색해질 수 있습니다
("접시를 집어서 접시에 놓아라" 같은).

그것 자체가 영향을 줄 수 있으니, 실제로 어떤 문장을 넣었는지 그림 설명에 같이 적으세요.
`lang_variants`에 저장돼 있습니다.

### 5. 모델 추가할 때

`configs/eval.yaml`을 보면 GR00T와 OpenVLA는 사진을 원본 크기(256픽셀) 그대로 보냅니다.
π0.5를 추가하려면 224픽셀로 줄여서 보내야 합니다. 공식 코드가 그렇게 하거든요.
