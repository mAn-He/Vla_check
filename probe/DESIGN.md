# 인지 / 계획 / 제어 3층 프로브 설계

## 전제: 이 모델들은 모놀리식이다

GR00T N1.7 과 OpenVLA-OFT 는 `(image, wrist_image, state, instruction) -> action chunk (T,7)`
를 한 번에 내놓는다. 인지·계획·제어 모듈이 따로 있는 게 아니다.

따라서 세 층은 **구조가 아니라 분석 렌즈**다. 각 층을 직접 뜯어보는 대신,
**입력을 조작하고 출력 변화를 관찰**해서 간접적으로 드러낸다.
이 방식의 장점은 모델 내부 구현에 의존하지 않아 **세 모델에 똑같이 적용**된다는 것이다.

핵심 아이디어: **관측 하나를 얼려놓고(frozen observation) 그 위에서 전부 측정한다.**
롤아웃을 돌릴 필요가 없으므로 저렴하고, 모델 간 조건이 완벽히 동일하다.

## 층 1 — 인지 (Perception): 무엇을 보는가

### P1. 가림 민감도 (Occlusion sensitivity)

이미지를 격자로 나누고 한 칸씩 가린 뒤, 예측 액션이 얼마나 달라지는지 잰다.

```
score(i,j) = || a(image) - a(image with patch (i,j) masked) ||
```

- 모델 내부 접근 불필요. 완전 블랙박스. 세 모델에 동일 적용.
- 결과: 원본 씬 위에 겹친 **saliency heatmap** (모델별 1장)
- 읽는 법: 대상 물체에 집중 → 인지가 태스크 지향적.
  배경·로봇 팔·조명에 반응 → 관련 없는 특징에 의존.

### P2. 카메라 기여도 분해

`agentview`(3인칭)와 `wrist`(손목) 중 어느 쪽에 의존하는가.
각각을 통째로 가리고 액션 변화량을 비교한다.

- 결과: 모델별 막대그래프 (agentview 의존도 vs wrist 의존도)
- 읽는 법: wrist 의존이 높으면 근접 조작 중심, agentview 의존이 높으면 공간 파악 중심.

### P3. 언어 개입 지점

같은 이미지에 지시문만 바꾼다.
```
(a) 원본 지시
(b) 동의어 치환   "pick up" -> "grab", "place" -> "put"
(c) 대상 교체     "black bowl" -> "plate"
(d) 빈 문자열
(e) 무관한 문장   "the weather is nice today"
```
- (b)에서 액션이 크게 변하면 → 문자열 패턴 암기
- (d),(e)에서 액션이 안 변하면 → 지시를 사실상 무시하고 이미지만 보고 있음
- 결과: 지시 변형 × 모델 액션 거리 heatmap

## 층 2 — 계획 (Planning): 무엇을 하려 하는가

### L1. 의도 궤적 (Intent trajectory)

액션 청크는 그 자체로 **단기 계획**이다. 얼린 관측 하나에서 받은 청크를
현재 EEF 위치에서 적분하면 "이 모델이 앞으로 T스텝 동안 가려는 경로"가 나온다.

```
p_0 = state[:3]                  # 현재 EEF 위치
p_{t+1} = p_t + delta_t          # 청크의 각 delta 를 누적
```

- 결과: **3D 궤적 플롯**. 모델별 색을 달리해 겹쳐 그린다.
- 읽는 법: 같은 장면에서 서로 다른 접근 경로를 그리면 계획이 다른 것.
  청크 길이가 다르면(GR00T vs OFT=8) 계획 지평도 다르다.

### L2. 계획의 언어 조건성

P3의 지시 변형별로 L1 궤적을 각각 그린다.
- 대상을 바꿨을 때(c) 궤적이 다른 물체 쪽으로 휘면 → 언어가 계획을 실제로 조건화
- 궤적이 그대로면 → 언어와 무관하게 장면만 보고 계획

이게 **"VLA 가 언어를 이해하는가"에 대한 가장 직접적인 시각 증거**다.

### L3. 계획 지평 일관성

청크 안에서 스텝이 진행될수록 불확실성이 커지는가.
얼린 관측에서 받은 청크 vs 한 스텝 실행 후 다시 받은 청크를 겹쳐 비교한다.
- 재계획 시 궤적이 크게 튀면 계획이 불안정
- 결과: 청크 겹침 플롯 + 재계획 편차 곡선

## 층 3 — 제어 (Control): 어떻게 실행하는가

### C1. 액션 매끄러움

성공한 에피소드의 액션 시계열에서 jerk(2차 차분)를 잰다.
```
jerk_t = a_{t+1} - 2*a_t + a_{t-1}
```
- 둘 다 성공해도 한쪽이 훨씬 덜컥거릴 수 있다.
- 실제 로봇에서는 매끄러움이 곧 하드웨어 수명·안전이다.
- 결과: 모델별 액션 7차원 시계열 + jerk 분포

### C2. 그리퍼 타이밍

7번째 차원(그리퍼)이 언제 닫히고 열리는가.
- 너무 일찍 닫으면 물체를 밀어냄, 너무 늦으면 놓침
- 결과: 시간축 위의 그리퍼 상태 비교

### C3. 결정성 / 입력 민감도

같은 관측을 N번 보내서 출력이 동일한가(결정성), 그리고
관측에 작은 가우시안 노이즈를 얹었을 때 출력이 얼마나 변하는가(민감도).

```
sensitivity = || a(o) - a(o + eps) || / ||eps||
```
- 민감도가 높으면 제어가 불안정. 실제 카메라 노이즈에 취약.
- 결과: 노이즈 강도 vs 액션 변화량 곡선 (모델별)

### C4. 효율

성공한 에피소드의 스텝 수. 이미 `results/*.jsonl` 에 기록돼 있으므로 추가 실행 불필요.
- 97% vs 98% 는 구분이 안 되지만, 91스텝 vs 121스텝은 명확한 차이다.

## 이 설계가 성공률 비교보다 나은 이유

1. **변별력** — 97% vs 98% 는 무의미하지만, saliency 가 다른 곳을 보고 궤적이 다른 방향으로
   휘면 그건 명백한 차이다.
2. **설명력** — "왜 이 모델이 나은가"에 답할 수 있다. 성공률은 답을 못 준다.
3. **재사용성** — 새 모델(π0.5)을 추가해도 같은 프로브가 그대로 돈다.
4. **시각화** — 숫자 표가 아니라 그림이 나온다. 포트폴리오로서의 전달력이 다르다.
5. **벤치마크 포화 회피** — LIBERO 표준 점수가 포화됐다는 건 알려진 문제다.
   프로브는 포화와 무관하게 차이를 드러낸다.
